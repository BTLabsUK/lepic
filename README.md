**An Epic Cash client library and command-line wallet in Rust.**

> [!WARNING]
> **Before 1.0.** Commands, the API and data formats can change between minor versions. A wallet's data is migrated when a newer release opens it, and the migration is one way, so back up the data directory first (see [Backup](docs/cli.md#backup)).

Welcome to LEPIC, a light wallet for Epic Cash. It creates and restores wallets, sends and receives
EPIC, takes payments through epic1 addresses and links, and exchanges transactions with people who
use the standard `epic-wallet`. It asks an Epic node for chain data, so it does not mine or store
the chain. No earlier knowledge of Epic is needed to try it.

There are four ways to use it:

| Way | Use it when |
|---|---|
| [`lepic` command-line wallet](docs/cli.md) | You want to try the wallet in a terminal or drive it from scripts. |
| [`lepic serve`](docs/api/README.md) | A bot, shop or service needs a running wallet with a local HTTP API (`/api/v1`, webhooks). |
| [Rust crates](docs/architecture.md#crates) | You want the wallet inside your own Rust program. |
| [FFI](docs/ffi.md) (`lepic-ffi`) | You build a desktop or mobile app. BT Wallet is built on it. |

The quickest first step is the CLI. Build it and create a wallet (needs Rust 1.100 or later):

```bash
cargo build --release -p lepic-cli
./target/release/lepic wallet init
```

The [CLI guide](docs/cli.md) continues from there with receiving, sending and checking a balance.
The same documents, with a command search and an API explorer, are at
[docs.btlabs.uk/developers/lepic](https://docs.btlabs.uk/developers/lepic/).

## Shape

| Part | What it is | Where |
|---|---|---|
| Library | The engine and its crates, used in-process from Rust | [`crates/`](docs/architecture.md#crates) |
| CLI | `lepic`, a command-line wallet on the same engine, with an interactive shell | [CLI](docs/cli.md) |
| Service API | `lepic serve`, the wallet API for a service that takes payments (`/api/v1`, webhooks) | [API guide](docs/api/README.md) |
| FFI | `lepic-ffi`, the API desktop and mobile apps call through flutter_rust_bridge | [FFI](docs/ffi.md) |
| Flutter binding | `lepic-flutter`, the Dart package over the FFI library | [its own repository](https://github.com/BTLabsUK/lepic-flutter) |

How a slate travels:

- By file
- Over Epicbox, with push sessions (`mux/1`) where the relay offers them
- Directly over HTTP or Tor
- LEPIC to LEPIC only: as a sealed slate (EPICTX) to a paired contact or an epic1 link
- LEPIC to LEPIC only: in person, as QR codes

Formats: [protocols](docs/protocols/README.md). Settings: [configuration](docs/configuration.md).

## Upstream matching

LEPIC reimplements the transaction, key and slate logic of the Epic node and `epic-wallet` instead
of linking their code. The reference releases are `epic-wallet` `v4.1.0`
([ADR 0020](docs/adr/0020-reference-epic-wallet-4-1.md)) and the Epic node `v4.1.2`
([ADR 0038](docs/adr/0038-reference-node-4-1-2.md)), at exact commits.

- [`upstream.toml`](upstream.toml) records the upstream files each ported module follows.
  `cargo xtask upstream-drift` lists upstream commits to those files after the recorded ones.
- The golden vectors in `testdata/vectors/` are generated by the pinned Epic Cash code in
  `conformance/`, and LEPIC's tests reproduce them byte for byte.
- The [interop suite](interop/README.md) runs LEPIC against an unmodified `epic-wallet`, node and
  Epicbox relay on a private test network.
- The cryptography library is the one Epic Cash uses, vendored in
  `third_party/epic_secp256k1zkp` with its changes listed in `PATCHES.md`.

The [compatibility notes](docs/compat/legacy-slates.md) in `docs/compat/` describe each format
LEPIC matches.

## Quick start

You need Rust through `rustup` and a C compiler. The repository pins Rust 1.100.0 in
`rust-toolchain.toml`. The crates are not published on crates.io; take them from git:

```toml
[dependencies]
lepic-wallet = { git = "https://github.com/BTLabsUK/lepic" }
lepic-primitives = { git = "https://github.com/BTLabsUK/lepic" }
```

Read a slate file from `epic-wallet` without opening a wallet:

```rust
use lepic_primitives::params::Network;
use lepic_wallet::slate::{CodecRegistry, MediaType, V2JsonCodec, V3JsonCodec, WireSlate};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let path = std::env::args().nth(1).ok_or("usage: inspect <slate.json>")?;
    let json = std::fs::read_to_string(path)?;

    // The V3 and V2 JSON formats epic-wallet reads and writes, at mainnet's base fee.
    let base_fee = Network::Mainnet.params().default_base_fee();
    let mut codecs = CodecRegistry::new();
    codecs.register(Box::new(V3JsonCodec::new(base_fee)))?;
    codecs.register(Box::new(V2JsonCodec::new(base_fee)))?;

    // A malformed slate is a typed error.
    let slate = codecs.decode(&WireSlate::text(MediaType::JSON, json))?;
    println!(
        "{} {:?}: amount {}, fee {} (base units)",
        slate.id(),
        slate.stage(),
        slate.amount().value(),
        slate.fee().value(),
    );
    Ok(())
}
```

The full wallet (create or restore, scan, send and receive) is the `lepic-wallet` engine with its
ports; [architecture](docs/architecture.md#ports) lists them. From the shell it is the
[`lepic` CLI](docs/cli.md). A Flutter app uses the
[Flutter binding](https://github.com/BTLabsUK/lepic-flutter).

## Build from source

You need Git, Rust through `rustup` (it installs the pinned 1.100.0 on the first command) and a C
compiler.

```bash
git clone https://github.com/BTLabsUK/lepic && cd lepic
cargo build --release            # every crate and the lepic CLI
cargo xtask install              # build lepic and install it into ~/.local/bin
cargo xtask install --dir /opt/lepic/bin
```

`cargo xtask mobile --package` builds the release `lepic-ffi` library for desktop and mobile apps, into
`dist/native/<triple>/` with a `SHA256SUMS` file. Without `--target` it builds every target the
host can build:

| Target | Builds on | Extra tools |
|---|---|---|
| `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android` | any host | Android NDK and `cargo-ndk` (API level 24) |
| `aarch64-apple-ios`, `aarch64-apple-ios-sim` | macOS | Xcode |
| `x86_64-unknown-linux-gnu` | Linux | none |
| `x86_64-pc-windows-msvc` | Windows | Visual Studio Build Tools (C++) |

The `lepic` CLI also runs on Windows. `lepic serve`, and anything that needs it, is Unix only.

```bash
cargo xtask mobile --package --target aarch64-linux-android
cargo xtask mobile --package --no-tor   # without Tor (ADR 0026), into dist/native-no-tor/
```

The Flutter binding runs this step from its own build. `cargo xtask` with no command prints the
list of commands.

## Testing

```bash
cargo xtask check                # the full gate: fmt, clippy, tests, cargo deny and the repo lints
cargo nextest run -p lepic-wallet            # one crate
cargo nextest run -p lepic-cli -E 'test(/^api_tls::/)'   # one test file of a crate (its module)
cargo test --workspace --doc     # doctests; nextest does not run them
```

Tests run under [cargo-nextest](https://nexte.st) (`cargo install cargo-nextest --locked`): each test
in its own process, so one crash fails one test. The integration tests of a crate with many test
files are one binary (`tests/<name>/main.rs`, one `mod` per former file), because every test
binary links the whole crate again; a new test file is a new `mod` line there. Dev and test builds
keep line tables only (`[profile.dev]`), enough for panic backtraces with line numbers; for a
debugger, build with `CARGO_PROFILE_DEV_DEBUG=2`.

`cargo xtask check` is the gate every change passes; run it from a git checkout, because it lists
files through `git`. Tests do not use the network. The few live tests are `#[ignore]`d and need
`LEPIC_LIVE_TESTS=1`.

Three suites sit outside the workspace:

- `conformance/` builds the pinned Epic Cash code, generates the golden vectors and runs the
  differential tests (`cd conformance && cargo test --locked`).
- `fuzz/` holds the fuzz targets for parsers of untrusted input ([fuzzing](docs/fuzzing.md)).
- `interop/` runs LEPIC against `epic-wallet`, the node and an Epicbox relay in Docker
  ([interop suite](interop/README.md)).

## Project structure

| Path | Layer | Contents |
|---|---|---|
| `crates/lepic-crypto`, `lepic-primitives`, `lepic-keychain` | pure | Commitments, proofs and signatures; transactions, fees and chain parameters; keys and the seed vault |
| `crates/lepic-slate`, `lepic-legacy-slate`, `lepic-native-slate` | pure | The slate model and codec registry; the V2/V3 JSON codecs; the binary `lepic.v1` slate |
| `crates/lepic-seal`, `lepic-contact` | pure | Sealed envelopes and contact cards; pairing messages |
| `crates/lepic-node`, `lepic-store` | I/O | Epic node client; wallet database |
| `crates/lepic-transport`, `lepic-epicbox`, `lepic-epic1` | I/O | Transport traits and the file method; Epicbox; the epic1 address and link |
| `crates/lepic-peer`, `lepic-legacy-rpc`, `lepic-tor` | I/O | The epic1 inbox endpoint; the `epic-wallet` foreign API over HTTP; onion service and client |
| `crates/lepic-telemetry` | I/O | Logging and redaction for the hosts |
| `crates/lepic-wallet` | engine | The wallet |
| `crates/lepic-methods` | methods | The file, http, tor and epicbox methods |
| `crates/lepic-wallet-contacts` | contacts | Pairing, contact mailboxes, epic1 payments, the delivery layer |
| `crates/lepic-cli`, `lepic-ffi` | host | The `lepic` CLI; the FFI API for Flutter apps |
| `xtask/` | tooling | `cargo xtask` commands |
| `testdata/vectors/` | data | Golden vectors from the pinned Epic Cash code |
| `docs/` | docs | Architecture, protocols, ADRs, RFCs, compatibility notes |

Each crate has a README; [architecture](docs/architecture.md) shows how they depend on each other.
